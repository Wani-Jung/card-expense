### 판(flavor) 구성

`flavorDimensions = "edition"`, flavor 는 **public(일반판)** 과 **full(전용판)** 두 개뿐이다. 그 밖의 flavor 는 없다.
두 판은 applicationId·서명키가 같아서 서로 덮어 설치해도 데이터가 유지된다.

| | 일반판 (`public`) | 전용판 (`full`) |
|---|---|---|
| Release 파일 | `app-release.apk` | `app-full-release.apk` |
| 문자 권한 | 없음 | `RECEIVE_SMS`, `READ_SMS` |
| SMS 수신 리시버 (`SmsReceiver`) | 없음 | 있음 (`src/full/AndroidManifest.xml`) |
| 지난 문자 1년치 불러오기 | 없음 (`Flavor.readInbox` 가 `null`) | 있음 (SMS·MMS·기타 저장소) |
| 알림 감지·붙여넣기·공유·캡처 OCR | 있음 | 있음 |
| 권한 설정 화면 '문자 읽기' 항목 | 안 보임 | 보임 |
| Dart 판별 | `isFullEdition == false` | `appFlavor == 'full'` |

- 판 구분 코드: Dart `lib/flavor.dart`, Kotlin `android/app/src/{public,full}/kotlin/.../Flavor.kt`.
- flavor 없이 실행하면(테스트 등) 일반판으로 동작한다.
- 일반판 APK 에 문자 권한이 섞이면 CI 가 배포를 막는다(8장). 이렇게 나눈 이유는 git 기록상 v1.2.0 "Play Protect 차단 회피" 때문이다.

## 2. 화면 구성

### 2-0. 공통

- 테마: 흰 바탕의 무채색 Material 3 테마(`buildTheme()`).
  - 포인트 색은 골드 `#F0A500`, 골드 위 글자는 `#3E2700`.
  - 기본 글자 `#1F1F1F`, 보조 글자 `#5F6368`, 선 `#E0E0E0`, 연회색 바탕 `#F5F5F5`.
- edge-to-edge 화면이다. 상태바·내비게이션 바가 투명하다.
  - 스크롤 목록 끝에는 `listBottomPad` 만큼 여백을 둔다: `max(하단 바 높이, 48) + 24`.
- 화면 회전 고정 설정은 매니페스트에 없다. 회전 동작은 **(확인 필요)**.

### 2-1. 첫 실행 설정 화면 (`SettingsScreen`)

- 카드번호 또는 발신번호가 저장돼 있지 않으면 메인 대신 이 화면이 뜬다.
- 제목은 '카드 문자 설정'이다.
- 입력칸:
  - **카드번호 네자리**: 숫자 4자리만 입력된다. 안내 "승인 문자에 적힌 카드번호 네자리 (예: "NH기업0000승인" 이면 0000)".
  - **발신번호**: 기본값 `1588-1600`. 숫자·`+`·`-`·공백만 입력된다. 옆에 [기본값으로] 버튼이 있다.
- [저장]은 카드번호가 4자리이고 발신번호가 숫자 7자리 이상일 때만 눌린다.
- 저장하면 다음이 일어난다.
  - shared_preferences 와 네이티브 저장소에 저장한다(`Native.setSettings`).
  - 값이 하나라도 바뀌었으면 1년치 자동 불러오기 표시(`auto_import_done`)를 지운다.
- 메뉴 > 카드 문자 설정에서도 같은 화면이 열린다.

### 2-2. 메인 화면 (`HomeScreen`)

**AppBar**
- 가운데에 '공감카드 관리' + 카드번호 4자리(작은 회색 고정폭 글씨)가 보인다.
- 오른쪽 톱니 아이콘(툴팁 '메뉴')을 누르면 메뉴로 간다.
- 화면을 아래로 당기면 새로고침된다(`_onResume`).
  - 네이티브 inbox 가져오기, 공유 텍스트 가져오기, 권한 상태 갱신을 한다.

**화면 구조: 틀고정 (v1.20.0)**
- 위쪽 **고정 영역** = 월 진행 표시줄 + ◀ 제목 ▶ + 요약표. 그 아래 1px 구분선(테마 divider 색), 그 아래 영역만 세로로 스크롤한다(엑셀 틀고정처럼).
- 스크롤 영역 순서: 권한 안내 배너 → 분류 대기 → 확인 필요 안내 줄 → 내역 목록. 아래로 당기면 새로고침.
- 고정 영역 높이가 화면 높이의 절반을 넘으면(작은 화면·큰 글씨) 고정을 풀고 전체를 한 번에 스크롤한다(`_checkFreeze`, 그린 뒤 높이를 재서 판단).
- 요약표 가로 스와이프는 가로 드래그 인식기가 먼저 잡으므로, 미는 동안 화면이 위아래로 흔들리지 않는다. 넘김 판단(60px·플릭, 가로 > 세로×2)은 그대로다.

**화면 요소 (아래 번호는 예전 순서 기준 설명. 실제 배치는 위 '화면 구조')**
1. **권한 안내 배너** (골드 연한 바탕 `#FFF8E6`)
   - 조건: '앱에서 사용'이 켜져 있는데 시스템 권한이 꺼진 항목이 있을 때만 보인다.
   - 버튼: [문자 권한](전용판), [알림 접근 켜기], '버튼을 눌러도 안 뜨면 → 앱 설정 열기'.
2. **분류 대기 N건**: 분류 안 된 내역이 최신순으로 카드 형태로 보인다.
   - 카드 내용: 가맹점, 금액(승인취소면 빨간 '승인취소 -금액'), 일시, 원문 박스.
   - 버튼: [차량비](초록 `#2E7D32`/흰 글씨), [운영비](노랑 `#FFC107`/글씨 `#4E2A00`), [무시].
   - 추천이 있으면 추천 쪽 버튼 위에 작은 배지가 붙는다('추천' 또는 '지난번 차량비' 등). 반대쪽 버튼은 흐리게(투명도 0.4) 보인다.
3. **확인 필요 안내 줄**: "확인이 필요한 내역 N건 ›". 누르면 확인 필요 화면으로 간다.
   - [닫기]를 누르면 그때 있던 건의 키를 `check_banner_closed_v1` 에 저장한다. 새 건이 생기면 다시 보인다.
4. **월 진행 표시줄** (`_MonthStrip`)
   - 1~12월 숫자가 한 줄로 있다.
   - 선택된 달(합산 화면이면 두 달)은 골드 동그라미에 흰 숫자다.
   - 홀짝/짝홀 묶음은 연회색 캡슐 `#EDEDED` 로 표시된다.
   - 지난 달·이번 달 숫자는 `#5F6368`, 미래 달은 `#BDBDBD`. 이번 달 아래에는 작은 점이 있다.
   - 숫자를 누르면 그 달의 월 화면으로 간다(합산 아님).
5. **◀ 제목 ▶** (`_MonthHeader`)
   - 화살표는 좌우 끝 48×48 상자에 고정돼 있다(툴팁 '이전'/'다음').
   - 제목은 FittedBox 다. 예: "2026년 3월", "2026년 3~4월 합산", "2026년 12월~2027년 1월 합산".
6. **요약표** (`_BudgetTable`, 5장 참고)
   - 오른쪽 위에 '(단위: 만원)'과 보기 선택 팝업 '1개월 ▾ / 홀짝 ▾ / 짝홀 ▾'가 있다.
   - 팝업 항목: '1개월', '홀짝 (1·2월, 3·4월 …)', '짝홀 (2·3월, 4·5월 …)'. 현재 값에 체크가 표시된다.
   - 좌우로 밀면 넘어간다(스와이프).
7. **내역 목록**: 보고 있는 달(합산이면 두 달)의 차량비·운영비 내역이 최신순으로 나온다.
   - 왼쪽에 고정 배지가 있다. '차량' 초록 칸 흰 글씨, '운영' 노랑 칸 갈색 글씨, 44×32 크기.
   - 가맹점, 'MM/DD HH:mm (· 승인취소)', 금액(승인취소는 빨강, 음수)이 보인다.
   - 합산 화면이면 달이 바뀌는 곳에 작은 구분선이 들어간다.
   - 비어 있으면 '이 달 분류된 내역이 없어요' 또는 '이 기간 분류된 내역이 없어요'.

**팝업·바텀시트·스낵바 (메인)**

- **내역 편집 바텀시트**: 목록 항목을 누르면 열린다.
  - 가맹점·금액, 일시, 원문이 보인다.
  - 버튼: [차량비] [운영비], [미분류로 되돌리기] [무시]. 확인한 내역에서도 같은 시트다.
  - [삭제]는 v1.20.0 에서 없앴다. 영구 삭제라 되돌릴 수 없고, 승인취소 묶음 한쪽만 지우면 묶음이 꼬이고, 지운 문자를 다시 불러오면 새 내역으로 들어오기 때문에 [무시]를 쓴다.
- **수립 입력 다이얼로그**: 합계·차량비 수립 칸(연필 아이콘)을 누르면 열린다.
  - 제목 'N월 합계 수립' 또는 'N월 차량비 수립'. 만원 단위로 입력하고 소수점을 쓸 수 있다.
  - 안내 '예) 34.25 → 342,500원 · 비우면 지워져요'. 버튼은 [취소] [저장].
  - 합산 화면에서는 열리지 않는다(연필도 숨김).
- **같은 업체 일괄 정리 다이얼로그**: "'가맹점' 대기 내역 N건도 차량비로 정리할까요?" [이번 건만] [모두 정리]. 창 밖을 누르면 아무것도 하지 않는다.
- **분류·무시·되돌리기 스낵바**: '가맹점 · 차량비로 분류했어요' 같은 문구와 5초짜리 [되돌리기]가 뜬다.
  - [되돌리기]는 같이 정리된 건과 등록 업체 기억까지 원래대로 돌린다.
- **업데이트 다이얼로그**: '새 버전 vX.Y.Z가 있어요' [나중에] [업데이트] (8장).
- **불러오기·붙여넣기 결과**
  - 스낵바: '추가 N건 · 중복 N건 · …'.
  - 무시했던 문자가 있거나 승인 문자가 아닌 조각이 있으면 결과 다이얼로그가 뜬다.
    - '승인 문자 아님 N건 내용 보기'(최대 50건)를 펼쳐 볼 수 있다.
    - [무시했던 N건 다시 분류 대기로] 버튼이 있다.
- **1년치 불러오기 0건 다이얼로그**: '새로 불러온 문자가 없어요'.
  - 검사 건수(SMS, MMS, 기타 저장소), 발신번호 일치 건수, 카드번호 일치 건수를 보여 준다.
  - RCS 로 왔을 수 있으니 캡처 업로드를 쓰라고 안내한다.
- **1회 바로잡기 스낵바**: '취소·재결제 내역 N건을 바로잡았어요' (4-6).

### 2-4. 미분류 내역 (`UnclassifiedScreen`)

- 모든 달의 분류 대기 건이 최신순으로 나온다. 달이 바뀌는 곳에 'YYYY년 M월 ───' 구분선이 들어간다.
- 항목마다 작은 [차량비] [운영비] [무시] 버튼이 있다.
  - 추천 배지는 버튼 안에 들어간다(v1.13 부터 화면 밖 잘림 수정).
- 동작은 메인 분류 대기와 같다: 일괄 정리 묻기, 등록 업체 기억, 스낵바 되돌리기.
- 비어 있으면 '미분류 내역이 없어요'.

### 2-5. 확인 필요 내역 (`CheckScreen`)

- 규칙별 섹션 '규칙 이름 (N건)'이 나온다(규칙은 4-4 참고). 각 카드에 내용·이유·버튼이 있다.
  - 일반 카드: 일시·가맹점·금액, '현재 차량비/운영비', 이유. 버튼은 [이대로 맞아요]와 반대 분류로 바꾸는 'X로 변경'.
  - **중복 의심 카드**: 묶음 하나가 카드 하나다.
    - 가맹점·금액과 시간 칩들('YYYY.MM.DD HH:mm · 분류')이 나란히 보인다.
    - 버튼: [둘 다 맞아요] [하나 무시]. [하나 무시]는 가장 늦은 건을 사유 '중복'으로 무시하고, 원본은 가장 이른 건으로 남긴다.
  - **승인 후 취소 카드**: 'MM.DD · 가맹점 / 분류'와 'HH:mm 승인 94,000원 / HH:mm 취소 -94,000원 → 합계 0원'이 보인다.
    - 재결제가 있으면 'HH:mm 재결제 94,000원 있음' 줄이 추가된다.
    - 버튼은 [확인했어요] 하나다. 한 건씩 따로 분류·무시하는 버튼은 없다.
- 비어 있으면 '확인이 필요한 내역이 없어요'.

### 2-6. 무시한 내역 (`IgnoredScreen`)

사유별 묶음으로 보여 준다. 사유는 4-5 참고.

- **되살리기는 모두 미분류(분류 대기)로 보낸다**(v1.19.0). [대기로 되돌리기], [중복 아님 · 되살리기], 승인 후 취소 [되살리기] 모두 해당 건(취소 묶음이면 두 건)을 미분류 내역으로 옮긴다.
  - 사유 필드(`ignoreReason`·`dupOf`·`ignoredFrom`)를 지운다.
  - 스낵바 '미분류 내역으로 옮겼어요'(두 건이면 '2건을 …')가 뜬다. [보기]를 누르면 미분류 내역 화면으로 가고, 5초 [되돌리기]를 누르면 원래 무시 상태와 사유가 그대로 돌아온다.
  - 중복 쌍·취소 묶음의 재표시 방지 기억은 그대로 남는다([되돌리기]를 해도 남는다).
- **직접 무시 (N건)**: 작은 [차량비] [운영비] [대기로 되돌리기] 버튼과 추천 배지가 있다. 승인취소 묶음의 한쪽이면 [대기로 되돌리기]에 짝도 같이 따라간다.
  - [차량비]/[운영비]를 누르면 같은 업체의 다른 '직접 무시' 건과 분류 대기 건을 같이 정리할지 묻는다(v1.15.0). 문구: "'가맹점' 무시·대기 내역 N건도 …로 정리할까요?"
- **중복으로 무시 (N건)**: 분류 버튼과 추천 배지가 없다.
  - 회색 줄 '중복이라 무시함 · 원본 MM.DD HH:mm (차량비)'가 보인다. 원본을 못 찾으면 '원본 없음'.
  - 버튼은 [중복 아님 · 되살리기] 하나다. 누르면 미분류로 가고, 그 쌍을 기억해 다시 중복 의심에 뜨지 않게 한다.
- **취소로 상쇄 (N건)**: 원승인과 취소 두 건이 한 카드에 보인다(각 일시·승인/취소·금액, '취소로 상쇄 · 합계 0원').
  - 버튼은 [되살리기] 하나다. 누르면 두 건 모두 미분류로 간다(v1.19.0 부터 무시 전 분류로 돌리지 않음). 그 묶음을 기억해 다시 승인 후 취소에 뜨지 않게 한다.
- 비어 있으면 '무시한 내역이 없어요'.

### 2-7. 업체 관리 (`VendorScreen`)

- 맨 위 안내: '추천 순서: 자동 등록 업체 > 직접 등록 키워드 > 기본 키워드'.
- 섹션 두 개가 있다.
  - '추천 키워드': '직접 등록' / '기본 키워드 · 차량비' / '기본 키워드 · 운영비' 작은 묶음 제목(건수)으로 나눈다. 기본 키워드는 회색 부제 '기본 키워드'.
  - 기본 키워드를 지우면 지운 것으로 기억한다(`removedDefaults`). 업데이트 때 되살리지 않는다.
  - '자동 등록된 업체'
- 각 행은 [고정 배지] 이름 … [휴지통] 순서다.
  - 배지는 메인 목록과 같은 `CategoryBadge` 이고 눌리지 않는다.
  - 행을 누르면 바텀시트가 열린다: 이름, [차량비|운영비] 선택(현재 값 체크), [저장].
  - 휴지통을 누르면 "'이름'을 목록에서 뺄까요?" 확인 창(을/를 자동) [취소] [빼기]가 뜬다.
- **섹션별 [전체 삭제]** (v1.20.0, 섹션 제목 오른쪽 빨간 텍스트 버튼, 0개면 비활성). 두 섹션을 한 번에 지우는 버튼은 없다.
  - '추천 키워드' [전체 삭제]: 기본 + 직접 등록 키워드를 모두 지운다. 기본 키워드는 지운 목록(`removedDefaults`)에 넣어 업데이트 때 다시 생기지 않는다.
  - '자동 등록된 업체' [전체 삭제]: 자동 등록 업체만 지운다.
  - 확인 창: '추천 키워드 N개를 모두 삭제할까요?' / '자동 등록 업체 N개를 모두 삭제할까요?' [취소] [삭제]. 지운 뒤 스낵바 '…를 모두 삭제했어요' + 5초 [되돌리기](전부 원상 복구).
- 추천 키워드 목록 맨 아래 **[기본 키워드 다시 넣기]**: 목록에 없는 기본 키워드를 다시 넣고 지운 목록에서 뺀다(이미 있는 건 건너뜀). 스낵바 'N개를 다시 넣었어요'.
- 오른쪽 아래 '+ 추가' 버튼(FAB)을 누르면 '추천 키워드 추가' 다이얼로그가 열린다.
  - 키워드 입력, 차량비/운영비 선택, [취소] [추가].
  - 같은 키워드가 있으면 분류만 바꾼다.
- 목록 끝 여백은 FAB 에 가리지 않게 `listBottomPad + 104` 로 잡는다(위젯 테스트로 확인).

## 3. 문자 인식 흐름

### 3-1. 공통 판정·파싱 (`lib/sms_parser.dart` `parseSms`)

- **승인/취소 판정**
  - `requireCard=true` 면 본문(공백 제거)에 `카드번호4자리+승인` 또는 `카드번호4자리+취소`가 있어야 한다. 예: `NH기업0000승인`, `NH기업0000승인취소`.
  - `requireCard=false` 면(네이티브에서 이미 거른 문자) '승인' 또는 '취소'만 본다.
- **금액**: 정규식 `(\d{1,3}(?:,\d{3})+|\d+)\s*원` 의 첫 매치. '체크' 글자는 없어도 된다(테스트로 확인).
- **일시**: `MM/DD HH:mm`. 문자에 연도가 없으므로 받은 시각의 연도를 쓰고, 받은 시각보다 하루 넘게 미래면 작년으로 본다.
- **가맹점**: 일시 다음 첫 줄. '누적' 뒤는 자르고 찌꺼기(따옴표·중괄호 등)는 지운다.
- **취소 여부**: 본문(공백 제거)에 '취소'가 있으면 승인취소다(`isCancel`). 합계에는 음수로 들어간다.
- **RCS JSON 본문**: JSON 이면 디코드해서 '원' + '승인/취소'가 든 문자열만 꺼낸다(`normalizeBody`).
- **내역 id (중복 판정 키)**: `일시(ISO)|금액|A 또는 C`. 가맹점은 넣지 않는다(알림은 가맹점이 잘려 올 수 있어서).

| **공유** | 두 판 | 메시지 앱 → 공유 → 공감카드 관리 (`SEND`/`SEND_MULTIPLE` text/plain) | `MainActivity` 가 받아 두고 Dart `takeShared` → 붙여넣기와 같은 쪼개기·판정 | 분류 대기 |
| **캡처 OCR** | 두 판 | `OcrScreen` + `lib/ocr_parse.dart` | OCR 보정(O·I·l→숫자, 금액 마침표·공백→쉼표, 날짜 공백 제거, RCS 화면 글자 제거) → 카드번호+승인 있는 조각만 후보. 금액·날짜 못 읽으면 '확인 필요'(valid=false)로 남겨 직접 고치게 함 | 분류 대기 (선택한 건) |

- **네이티브 inbox → 앱**: 앱이 켜져 있으면 `onNewSms` 로 바로 가져간다. 꺼져 있었으면 다음에 켜거나 돌아올 때(`resumed`) 가져간다. 이때 `requireCard: false` 로 파싱한다.
- **앱 알림 없음**: 이 앱은 상태바 알림을 띄우지 않는다. `NotificationManager`·`POST_NOTIFICATIONS` 사용이 코드에 없다. 조용히 쌓아 두고, 앱을 열면 보인다.

### 3-3. 중복 방지 (3단계)

1. **네이티브** (`CardSms.handle`): 키 `M/D H:mm|금액|A/C` 를 `seen` 목록(최근 300개)에서 확인한다. 알림과 SMS 양쪽에서 같은 건이 와도 한 번만 쌓는다.
2. **수집 분류** (`classifyMessages`): 같은 묶음 안에서 같은 id 는 '중복'이다. 저장된 내역에 같은 id 가 있으면 다음과 같이 나눈다.
   - 분류됐거나 대기 중이면 '중복'
   - 무시한 건이면 '무시했던 문자'(되살리기 가능)
   - 승인 문자로 못 읽으면 '승인 문자 아님'
3. **저장** (`_addParsed`): 이미 있는 id 는 넣지 않는다.

- **영문·숫자 3자 이하 키워드**(예: `LPG`)는 가맹점 이름 **앞부분 일치**일 때만 맞는 것으로 본다(엉뚱한 부분 일치 방지). 직접 등록 키워드도 같은 규칙이다.
- 키워드 비교는 대소문자·공백·하이픈·밑줄·점·가운뎃점을 무시한다(`keywordKey`).
- 추천 우선순위: **자동 등록 업체**(가맹점 이름 일치) > **직접 등록 키워드** > **기본 키워드**. 같은 단계 안에서는 긴 키워드가 먼저다.
- 추천은 버튼 위 배지로 보인다. 등록 업체면 '지난번 차량비/운영비', 키워드면 '추천'.

### 4-2. 등록 업체 학습

- 차량비/운영비로 분류할 때마다 그 가맹점을 '자동 등록된 업체'로 기억한다. 마지막에 고른 분류가 기준이다.
- 키는 `merchantKey` 다. 키워드 비교 규칙에 더해 `(주)`·`㈜`·`주식회사`·괄호·따옴표·쉼표·슬래시를 무시한다. 예: "(주)홍성 칼국수" = "홍성칼국수".
- 스낵바 [되돌리기]를 누르면 학습 전 상태로 돌린다.

### 4-3. 같은 업체 일괄 정리 (`sameVendorPending`)

| 어디서 고를 때 | 같이 정리하는 대상 | 제외 |
|---|---|---|
| 메인 분류 대기, 미분류 내역 | 같은 `merchantKey` 의 **분류 대기** 건 | 무시한 건, 분류된 건 |
| 무시한 내역 (v1.15.0) | 같은 업체의 **분류 대기** + **직접 무시** 건 | '중복'·'취소로 상쇄'로 무시한 건, 분류된 건 |

- 확인 필요 화면의 'X로 변경'과 메인 내역 편집 시트에서는 일괄 정리를 묻지 않는다. 이미 분류된 같은 업체 건도 옮기지 않는다.
- 승인취소 묶음(4-6)에 들어간 건은 어디서 분류하든 짝까지 같이 바뀐다.

### 4-4. 확인 필요 규칙 (`lib/check.dart` `findIssues`)

**분류된(차량비·운영비) 건만** 본다. 대기·무시 건은 대상이 아니다. 섹션 순서는 아래 표의 순서다.

| 규칙 (화면 제목) | 조건 | 이유 문구 (요지) |
|---|---|---|
| a. 같은 업체인데 분류가 다른 건 | 같은 `merchantKey` 안에서 차량·운영이 섞여 있으면 소수 쪽 건. 반반이면 표시 안 함 | '평소엔 차량비로 분류한 업체예요 (10건 중 9건)' |
| b. 추천·등록 업체와 반대로 분류한 건 | 추천과 다른 분류. a 에 걸린 건은 제외. 등록 업체 기준이면서 분류가 섞인 업체도 제외(a 가 맡음) | '등록 업체는 운영비인데 차량비로 분류했어요' / '차량비 추천 키워드가 들어 있는 가맹점이에요' |
| c. 중복 의심 | 같은 가맹점·같은 금액·같은 승인/취소가 10분 이내에 2건 이상. **취소 묶음에 들어간 건은 제외**. 맞다고 기억한 쌍은 제외 | '같은 결제가 N번 들어온 것 같아요' (묶음 하나 = 카드 하나, 대표는 가장 늦은 건) |
| 승인 후 취소 | 원승인·취소가 둘 다 분류된 취소 묶음 | '승인했다가 취소한 결제예요. 합계는 0원이에요' + 재결제(취소 후 24시간 안, 같은 가맹점·금액, 다른 묶음·무시가 아닌 승인)가 있으면 표시 |
| d. 승인취소 짝이 안 맞는 건 | 분류된 취소인데 묶인 원승인이 없음 / 원승인이 분류돼 있고 분류가 다름 | '같은 금액의 원래 승인 내역이 없는 취소예요' / '원래 승인(…)은 차량비로 분류돼 있어요' |
| e. 날짜 이상 | 지금보다 10분 넘게 미래 / 365일보다 오래됨 | '미래 날짜예요…' / '1년보다 오래된 날짜예요…' |

- 같은 규칙 안에서는 최신순이다.
- 기억(`check_ok_v1`) 키:
  - a·b·d·e 의 [이대로 맞아요]: `규칙이름|내역id`
  - 중복 [둘 다 맞아요]: 쌍마다 `dup|id|id`(정렬). v1.12 의 `duplicate|id` 도 두 건 모두 있으면 인정한다.
  - 승인 후 취소 [되살리기]: `cancelled|원승인id+취소id`
- 메인 안내 줄 닫기(`check_banner_closed_v1`): 그때의 issue 키 목록을 저장한다.

### 4-5. 무시 사유 (`Expense.ignoreReason`, 3종)

| 사유 | 값 | 생기는 곳 | 추가 필드 |
|---|---|---|---|
| 직접 무시 | `manual` (필드 없는 예전 데이터도 직접 무시로 봄) | 메인 분류 대기·미분류 내역의 [무시] | — |

| 취소로 상쇄 | `offset` | 확인 필요 > 승인 후 취소 [확인했어요] (두 건 함께) | `ignoredFrom` = 무시 전 분류 |

### 4-6. 승인취소 묶음 (`lib/cancel_link.dart`, v1.14.0)

- **연결**: 승인취소를 시간순으로 하나씩 본다. 같은 `merchantKey`·같은 금액이고 취소보다 이전(같은 시각 포함)인 승인 중, **아직 안 묶인 가장 가까운 1건**을 원승인으로 묶는다.
  - 시각이 분 단위라서, 취소와 같은 분의 승인은 그보다 이전 승인이 하나도 없을 때만 고른다.
  - 예: 13:23 승인 → 13:24 취소 → 13:24 재승인이면 원승인은 13:23 이다.
  - 분류 여부와 상관없이 전체 내역에서 찾는다(무시·대기 포함).
- **합계**: 두 건 모두 반영된다(+94,000 −94,000 = 0).
- **분류 따라가기**: 새로 들어온 취소가 원승인과 묶이고 원승인이 차량비·운영비면 취소도 같은 분류가 된다(`followOrigins`). 원승인이 대기면 그대로 둔다.
- **한 건씩 따로 분류·무시 불가**: `_classify` 가 묶인 짝까지 함께 바꾼다.
- **원승인 없는 취소**: d 규칙 '승인취소 짝이 안 맞는 건'으로 표시한다.
- **1회 바로잡기** (`fixCancelRebuys`, 키 `cancel_fix_v1`): 업데이트 후 앱을 처음 켤 때 한 번 실행한다.
  - '중복'으로 무시된 승인 중, 원본과의 사이에 같은 가맹점·금액의 취소가 있는 건(= 취소 뒤 재결제)을 원본 분류로 되살린다.
  - 묶인 취소의 분류를 원승인에 맞춘다.
  - 바꾼 건이 있으면 스낵바 '취소·재결제 내역 N건을 바로잡았어요'를 한 번 띄운다.

## 5. 요약표 계산 (`lib/budget.dart`, `_BudgetTable`)

### 5-1. 표 모양

|  | 수립 | 사용 | 잔여 |
|---|---|---|---|
| 합계 (`#F5F5F5` 칸, 굵게) | 입력 (연필) | 차량+운영 사용 | 수립 − 사용 |
| 차량비 (초록 `#2E7D32` 칸, 흰 글씨) | 입력 (연필) | 차량비 사용 | 수립 − 사용 |
| 운영비 (노랑 `#FFC107` 칸, 글씨 `#3E2C00`) | **자동** = 합계 − 차량비 (회색 글씨) | 운영비 사용 | **항상 빈 흰 칸** |

- 열 너비 비율은 1.0 / 1.1 / 1.1 / 1.4. 칸 최소 높이는 48, 테두리는 `#E0E0E0`(둥근 6).
- 머리 행: 빈칸·수립·사용은 `#F5F5F5`. '잔여' 머리 칸은 블루그레이 `#E3E9F3` 바탕에 네이비 `#1F3A68` 글씨.
- 단위는 **만원**, 소수점 둘째 자리까지 표시한다(`342500원 → 34.25`). 저장은 원 단위.

### 5-2. 공식

- **운영비 수립** = 합계 수립 − 차량비 수립. 둘 중 하나라도 비면 '-'.
  - 음수면(차량비 > 합계) 칸이 연빨강 `#FFEBEE` + 빨강 `#C62828` 굵은 글씨가 되고, 표 아래에 '차량비 수립이 합계보다 커요'가 뜬다.
- **사용** = 그 달 분류된 내역의 합(승인취소는 차감). 대기·무시 건은 제외.
- **잔여** = 행별 수립 − 사용(합계 행, 차량비 행만). 수립이 비면 '-', 음수면 '초과 X.XX'.
- **수립 이월**: 수립이 없는 달은 직전에 수립한 달 값을 그대로 쓴다. 한 칸을 바꾸면 그 달에만 저장한다(물려받던 다른 칸 값도 그 달에 복사).

### 5-3. 상태 3단계 (`budgetLevel`, 합계·차량비 잔여 칸)

| 단계 | 조건 | 잔여 칸 바탕 | 잔여 숫자 |
|---|---|---|---|
| 여유 | 사용 < 수립의 80% (수립이 비면 항상 여유) | `#F1F4F9` (블루그레이) | 네이비 `#1F3A68`, 굵게 18 |
| 주의 | 80% 이상 ~ 100% 이하 | `#F1F4F9` | 빨강 `#D93025` |
| 초과 | 100% 초과 | 빨강 `#D93025` | 흰색, '초과 X.XX' |

- **사용 칸**: 초과일 때만 빨강 `#D93025` 글씨다(주의 단계는 색이 바뀌지 않음). 운영비 사용 칸은 항상 기본색이다.

### 5-4. 보기 기간과 넘김

- 보기는 **1개월 / 홀짝 / 짝홀** 세 가지다. 저장하지 않으며, 앱을 켤 때마다 1개월로 시작한다.
  - 홀짝 묶음: (1·2)(3·4)…(11·12)
  - 짝홀 묶음: (2·3)(4·5)…(12·1). (12·1) 은 연도를 넘긴다.

## 7. 권한·설정

### 7-1. 매니페스트 권한 (릴리스 APK `aapt` 결과 기준)

| 권한 | 일반판 | 전용판 | 비고 |
|---|---|---|---|
| `INTERNET` | ✓ | ✓ | 업데이트 확인 (`src/main`) |
| `ACCESS_NETWORK_STATE` | ✓ | ✓ | 앱 매니페스트에는 없음. 의존 플러그인에서 병합된 것으로 보임 — 어느 플러그인인지 **(확인 필요)** |
| `com.wani.card_expense.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` | ✓ | ✓ | 빌드 도구가 자동으로 추가 (앱 코드에서 선언 안 함) |
| `RECEIVE_SMS`, `READ_SMS` | ✗ | ✓ | `src/full/AndroidManifest.xml` 에만 있음 |

- 서비스 `CardNotificationListener`: `BIND_NOTIFICATION_LISTENER_SERVICE`. 사용자가 휴대폰 설정에서 '알림 접근'을 허용해야 동작한다.
- 공유 받기 intent-filter: `SEND`, `SEND_MULTIPLE` (`text/plain`).
- `<queries>`: `PROCESS_TEXT`, `VIEW https` (업데이트 링크를 브라우저로 열기).
- 알림 표시 권한(`POST_NOTIFICATIONS`)과 저장소 권한은 없다. 사진은 Android 사진 선택기로 받는다.

### 7-2. 권한 설정 화면 (`lib/permission_screen.dart`)

| 항목 | 설명 | 스위치 '앱에서 사용' (기본 켜짐) | 시스템 권한 표시 / 버튼 |
|---|---|---|---|
| 알림 감지 (두 판) | 메시지 앱 알림에서 카드 승인 문자를 자동으로 찾아요 | 끄면 알림 리스너가 문자를 받아도 버린다 (분류 대기에 안 쌓임). 켰는데 시스템 권한이 꺼져 있으면 '휴대폰 설정에서 알림 접근을 허용해야 해요' 안내 후 알림 접근 설정을 연다 | '허용됨'(초록 `#1E8E3E`/바탕 `#E6F4EA`) 또는 '꺼짐'(회색). [설정 열기] → 알림 접근 설정 |

## 8. 배포

### 8-1. GitHub Actions (`.github/workflows/release-apk.yml`, 이름 'Build APK')

- **트리거**: `main` push, `v*` 태그 push, 수동 실행(`workflow_dispatch`).
- **순서**
  1. checkout
  2. Java 17 (temurin)
  3. Flutter 3.44.9 stable
  4. **keystore 복원**: Secret `ANDROID_KEYSTORE_BASE64` 를 디코드해 러너 임시 폴더에 `release.jks` 로 만든다. 없으면 실패.
  5. `flutter pub get`
  6. **`flutter test`** (실패하면 배포 안 함)
  7. 두 판을 빌드한다: `flutter build apk --release --flavor public/full`
     - `--build-number = github.run_number` (versionCode)
     - 태그 빌드면 `--build-name = 태그에서 v 를 뗀 값` (versionName)
  8. 결과물 이름: `dist/app-release.apk`(public), `dist/app-full-release.apk`(full)
  9. **일반판 APK 에 `RECEIVE_SMS`/`READ_SMS` 가 있으면 실패** (aapt 검사)
  10. 태그면 정식 릴리스로 올린다. 같은 태그 릴리스가 있으면 파일만 교체하고, 없으면 `--generate-notes --latest` 로 만든다.
  11. `main` push 면 `dev` 프리릴리스를 지우고 최신 커밋으로 다시 만든다(제목 '개발 빌드 (main 짧은커밋)').
- 모든 `main` push 가 `dev` 프리릴리스를 갱신한다. 정식 링크(`latest`)는 `v*` 태그 릴리스만 가리킨다.

### 8-2. 고정 링크

- 일반판: `https://github.com/Wani-Jung/card-expense/releases/latest/download/app-release.apk`
- 전용판: `https://github.com/Wani-Jung/card-expense/releases/latest/download/app-full-release.apk`
- 설치는 이 GitHub Release 링크로만 한다. adb·USB 설치는 쓰지 않는다(프로젝트 규칙, `CLAUDE.md`).
- v1.15.0 에서 두 링크 모두 익명으로 받아지는 것(HTTP 200)과 서명·권한·versionCode 37 을 CI 후에 확인했다.

### 8-3. 서명

- 키 값을 찾는 순서는 다음과 같다(`android/app/build.gradle.kts`).
  1. 로컬 `android/key.properties`
  2. 환경변수(CI 는 GitHub Secrets)
  3. 둘 다 없으면 debug 키(로컬에서만 해당. CI 는 keystore secret 이 없으면 4단계에서 실패)
- **로컬**: `android/key.properties` 가 저장소 밖 로컬 폴더의 keystore 파일을 가리킨다. `key.properties`, `*.jks`, `*.keystore` 는 `android/.gitignore` 로 커밋에서 빠진다.
- **CI**: GitHub 저장소 Secrets `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD` (이름만 적음).
- 업데이트 덮어쓰기 설치가 되려면 항상 같은 키여야 한다. v1.7.0~v1.15.0 릴리스 APK 의 서명 인증서가 같은 것을 매번 `apksigner` 로 확인했다.

### 8-4. 앱 안 업데이트 알림 (`lib/update_check.dart`, `_checkUpdate`)

- 조회: `https://api.github.com/repos/Wani-Jung/card-expense/releases/latest` (연결 8초, 응답 10초 제한).
  - 프리릴리스·초안은 무시한다. `v숫자.숫자.숫자` 태그만 인정한다.
- **자동 확인**: 앱을 켤 때 실행한다. 마지막 확인 후 20시간이 안 지났으면 건너뛴다.
  - 새 버전이 있고, [나중에]로 넘긴 태그가 아니면 다이얼로그를 띄운다.
- **수동 확인**: 메뉴 > 업데이트 확인. 결과에 따라 다음과 같이 보인다.
  - 최신이면 '최신 버전이에요 (vX · 판)'
  - 실패하면 '업데이트 정보를 확인하지 못했어요…'
  - 새 버전이 있으면 다이얼로그
- 다이얼로그 '새 버전 vX가 있어요 / 지금 버전 vY · 판'
  - [업데이트]: 브라우저로 **자기 판에 맞는** 고정 링크(일반판 → `app-release.apk`, 전용판 → `app-full-release.apk`)를 연다.
  - [나중에]: 그 태그를 `update_skipped_tag` 에 저장한다. 자동 확인에서는 다시 띄우지 않는다.
- 버전 비교는 major.minor.patch 숫자로만 한다(`isNewerVersion`).

### 11-3. 알려진 제한사항 (코드에서 확인)

1. **내역 id 에 가맹점이 없다** (`일시|금액|승인/취소`).
   - 같은 분·같은 금액의 승인 2건은 가맹점이 달라도 같은 건으로 보고 두 번째를 '중복'으로 버린다.
   - 같은 분·같은 금액·같은 가맹점의 재결제도 마찬가지다.
2. **네이티브 중복 방지 키에 연도가 없다** (`M/D H:mm|금액|A/C`, 최근 300개만 기억).
   - 기억 범위 안에서 1년 뒤 같은 날·같은 시각·같은 금액 문자가 오면 버려질 수 있다. 실제로 생길 가능성은 낮다.
3. **이미 분류된 같은 업체 건은 일괄로 안 바뀐다.** 메인 편집 시트(확인한 내역 포함)·확인 필요 'X로 변경'에서는 그 건(과 취소 묶음 짝)만 바뀐다.
4. ~~내역 편집 시트의 [삭제]가 한 건만 지워 묶음이 꼬임~~ → v1.20.0 에서 [삭제]를 없앰 ([무시] 사용).
5. ~~붙여넣기·캡처의 '무시했던 문자 되살리기'가 사유 필드를 남김~~ → v1.19.0 에서 해결 (`_revive` 도 `ignoreReason`·`dupOf`·`ignoredFrom` 을 지운다).
6. **승인 후 취소**: 분류된 취소 묶음은 [확인했어요]를 누르기 전까지 확인 필요 건수에 계속 들어간다(설계상 동작).
7. **1년치 불러오기 기간**은 365일로 고정이다. RCS 기업메시지는 기기에 따라 저장소가 막혀 있어 못 읽을 수 있다. 이때 0건 다이얼로그에서 캡처 업로드를 안내한다.
8. **연도 추정**: 문자에 연도가 없어서 받은 시각 기준으로 정한다. 받은 시각을 모르는 붙여넣기는 지금 시각 기준이다.
9. **네이티브 코드는 자동 테스트가 없다** (9장).
10. 확인 필요 규칙은 분류된 건만 본다. 대기·무시 건의 중복·날짜 이상은 검사하지 않는다.

| 설치는 GitHub 링크만 | 앱 안 업데이트는 판에 맞는 `releases/latest/download/...` 링크를 브라우저로 엶 | 일치 |

빌드노트에 없지만 알아 둘 점:

- APK versionCode 는 pubspec 의 `+N` 이 아니라 CI 실행 번호다(v1.15.0 = 37, v1.16.0 = 39, v1.17.0 = 42, v1.18.0 = 45, v1.19.0 = 48).
- `main` 에 push 할 때마다 `dev` 프리릴리스가 갱신된다. 고정 링크(`latest`)에는 영향이 없다.
- 운영비 수립은 입력 칸이 아니라 자동 계산이다. 차량비 수립이 합계보다 크면 빨간 칸과 경고 문구가 나온다.
- 요약표 합산 화면에서는 수립을 고칠 수 없다.
- 정산 텍스트 복사 기능은 v1.14.0 에서 완전히 삭제됐다.
